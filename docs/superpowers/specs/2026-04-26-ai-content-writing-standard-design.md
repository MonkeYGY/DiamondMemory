# AI软件内容写入规范 - 设计文档

## 基本信息
- **创建时间**: 2026-04-26
- **设计目标**: 统一所有AI软件写入钻石记忆系统的内容格式、元数据标准和展示规范
- **适用范围**: Hermes Agent、OpenClaw、未来所有接入钻石记忆系统的AI软件
- **核心原则**: 底层API使用英文字段，前端展示全部使用中文

---

## 一、问题背景

当前钻石记忆系统接入了多个AI软件（Hermes Agent、OpenClaw），各软件写入记忆时：
1. **内容格式不统一** - 有的用纯文本，有的用Markdown，结构混乱
2. **元数据字段不一致** - 缺少标准化的分类、标签体系
3. **详情页展示混乱** - 不同来源的内容排版差异大，阅读体验差
4. **L3-L6整理后文档名** - 可能使用英文命名，不够直观

---

## 二、规范设计

### 2.1 元数据字段规范（API层使用英文）

所有AI软件调用 `/api/memory/create` 时，必须包含以下字段：

| 字段名 | 类型 | 必填 | 说明 | 示例值 |
|--------|------|------|------|--------|
| `content` | string | ✅ | 正文内容（遵循内容格式规范） | 见下方 |
| `source` | string | ✅ | AI软件来源标识 | `hermes`, `openclaw` |
| `category` | string | ✅ | 一级分类（固定枚举值） | `conversation` |
| `tags` | array | ✅ | 标签列表（使用中文标准标签） | `["对话记录", "技术知识"]` |
| `confidence` | float | ✅ | 置信度 (0.0-1.0) | `0.95` |
| `layer` | int | ✅ | 写入层级（AI软件仅允许写入L1） | `1` |
| `metadata` | object | ⚠️ | 扩展元数据（按需填写） | `{}` |

**`metadata` 扩展字段：**

| 子字段 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| `agent_id` | string | 智能体ID（多智能体场景） | `hermes-main` |
| `session_id` | string | 会话ID | `sess-abc123` |
| `turn_number` | int | 对话轮次 | `5` |
| `word_count` | int | 内容字数 | `1200` |
| `is_complete` | bool | 是否为完整对话 | `true` |
| `original_url` | string | 原始来源URL（网页抓取场景） | `https://...` |

### 2.3 分类标签体系（中文显示）

#### 一级分类（category）- 前端中文映射

| API值 | 中文显示 | 说明 | 适用场景 |
|-------|----------|------|----------|
| `conversation` | 对话记录 | 用户与AI的日常对话 | 问答、讨论、决策 |
| `knowledge` | 知识记录 | 事实性知识、技术知识 | 技术文档、知识点 |
| `task` | 任务记录 | 自动化任务、执行记录 | 脚本执行、文件操作 |
| `preference` | 用户偏好 | 用户习惯、偏好设置 | 格式要求、工作习惯 |
| `insight` | 洞察分析 | AI的分析、建议 | 分析建议、优化方案 |

#### 二级标签（tags）- 标准中文标签库

**对话类**: `对话记录`, `问题解答`, `需求讨论`, `决策记录`
**知识类**: `知识点`, `技术规范`, `最佳实践`, `常见问题`
**任务类**: `任务执行`, `自动化脚本`, `文件操作`, `代码修改`
**偏好类**: `用户偏好`, `工作习惯`, `沟通风格`, `格式要求`
**洞察类**: `分析建议`, `优化方案`, `风险提示`, `趋势预测`

**标签规则：**
- 每条记忆必须至少包含1个标准标签
- 可自定义标签，但必须以 `自定义/` 前缀开头
- 标签使用中文，最多5个标签
- 技术专有名词可保留英文（如 `React`, `Python`, `Docker`），但作为标签时优先用中文（如 `Docker配置` 而非 `docker-config`）

### 2.4 L3-L6文档命名规范

当系统自动从L2整理到L3-L6时，文档命名遵循以下规则：

#### 2.4.1 L3分类目录命名（中文概括）

L3是**总结分类层**，类似文件夹，用于对L4经验进行分类组织。

| 场景 | 命名示例 | 说明 |
|------|----------|------|
| 技术文档 | `Docker配置指南` | 品牌名保留英文，描述用中文 |
| 最佳实践 | `React组件设计模式` | 技术名保留英文 |
| 用户偏好 | `代码格式偏好` | 全中文 |
| 项目文档 | `钻石记忆系统架构` | 全中文 |

**L3分类命名规则：**
- 长度限制：2-8个字，简短明确
- 优先使用中文概括内容
- 品牌名、技术专有名词保留原文（React、Python、Docker、FastAPI等）
- 不使用下划线或连字符，直接用中文空格或自然分隔
- 避免使用缩写（如 `dev` → `开发`, `config` → `配置`）
- 禁止使用无意义名称（如 `其他`、`未分类`、`默认`、`综合`）
- 使用名词短语，如 `Vue开发技巧`、`Linux运维指南`

#### 2.4.2 L4文档命名（经验总结）

L4是**经验总结层**，是具体的知识内容，类似文件。

| 场景 | 命名示例 | 说明 |
|------|----------|------|
| 具体知识 | `Docker镜像加速器配置方法` | 描述性标题 |
| 经验总结 | `前端性能优化核心要点` | 概括核心要点 |
| 问题解答 | `Vue3响应式数据丢失排查` | 问题+解决方案 |
| 项目记录 | `钻石记忆系统V0.7版本优化` | 项目+时间/版本 |

**L4内容格式要求：**
- 主题行：必须使用抽象的、可复用的名词短语，不超过15个字
- 主题行中**绝不允许**出现日期或时间（如 `20260424`），日期只能放在核心要点或详细记录中
- 内容结构必须包含：主题、核心要点、详细记录
- 概括总结内容用中文表述

**示例结构：**
```
主题: Docker配置最佳实践

核心要点:
- 时间: 2026-04-26
- Docker镜像加速器推荐使用阿里云源
- 配置文件位于 /etc/docker/daemon.json

详细记录:
在Linux系统中配置Docker镜像加速器可以显著提升拉取速度...
```

#### 2.4.3 L5-L6技能规范（参考ClawHub技能体系）

L5是**技能分类层**（目录层），L6是**技能层**（可复用的复杂工作流）。

**技能本质定义：**
- **技能不是简单的知识总结**，而是对**复杂工作流的打包**
- **复杂技能可以包含简单技能**（技能嵌套/组合）
- **调用技能是为了完成特定复杂工作**（如：部署项目、生成报告、分析数据、自动化测试）
- 技能 = 触发条件 + 工作流步骤 + 子技能引用 + 工具定义 + 最佳实践

**L5/L6命名示例：**

| 层级 | 场景 | 命名示例 | 说明 |
|------|------|----------|------|
| L5 | 技能分类 | `前端开发技能` | 2-8个字，名词短语 |
| L5 | 技能分类 | `自动化部署` | 动词+名词结构 |
| L5 | 技能分类 | `数据分析工作流` | 描述工作流领域 |
| L6 | 复杂技能 | `前端项目部署全流程` | 包含多个步骤的复杂工作流 |
| L6 | 复杂技能 | `技术文档自动生成` | 调用多个子技能的复合技能 |
| L6 | 简单技能 | `Git分支命名规范` | 单一规则/最佳实践 |

**L5技能分类命名规则：**
- 长度限制：2-8个字，简短明确
- 使用名词短语或动词+名词结构（如 `部署流程`、`代码审查`、`数据分析`）
- 优先使用中文概括内容，技术名词可保留英文
- 禁止使用无意义名称（如 `其他`、`通用`、`综合`、`未分类`）

**L6技能内容强制结构：**

```markdown
# 技能名称：前端项目部署全流程

## 目标任务
将前端项目从开发环境部署到生产环境，包含构建、测试、上传、验证等步骤

## 触发条件
- 用户说"部署前端项目"、"发布到生产"、"上线新版本"
- 用户提供了项目路径和部署目标

## 包含步骤/子技能
1. 【准备阶段】检查项目状态
   - 确认代码已提交且无未提交更改
   - 确认依赖已安装（`npm install`）
   
2. 【构建阶段】生产环境构建
   - 设置NODE_ENV=production
   - 执行构建命令（`npm run build`）
   - 检查构建产物是否正常生成

3. 【测试阶段】自动化测试（调用子技能：前端单元测试执行）
   - 运行单元测试（`npm run test`）
   - 运行端到端测试（`npm run e2e`）
   - 检查测试覆盖率是否达标

4. 【部署阶段】上传到服务器（调用子技能：服务器文件上传）
   - 连接目标服务器（SSH/FTP）
   - 备份当前版本
   - 上传新构建产物到指定目录

5. 【验证阶段】部署后检查
   - 访问部署地址确认页面正常加载
   - 检查关键功能是否正常
   - 发送部署通知

## 涉及工具
- Node.js/npm（构建）
- Jest/Cypress（测试）
- SSH/SCP（上传）
- 浏览器（验证）

## 最佳实践
- 部署前必须确保所有测试通过
- 使用CI/CD管道自动化部署流程
- 保留至少3个历史版本备份
- 部署失败时自动回滚到上一版本

## 依赖的子技能
- 前端单元测试执行
- 服务器文件上传
- Git分支管理规范

## 注意事项
- 生产环境部署需要管理员权限
- 部署过程中禁止中断操作
- 部署完成后必须手动验证核心功能
```

**L6技能提炼标准（何时从L4提炼为L6）：**

✅ **应该提炼为技能的情况：**
1. 内容包含**多个步骤/流程**，可复用于完成特定复杂任务
2. 内容描述了一个**完整的工作流**（如：从A到Z的完整过程）
3. 内容涉及**调用其他技能/工具**来完成工作
4. 用户明确要求"记住这个技能"、"以后这样操作"
5. 内容是**特定领域的最佳实践范式**（如：代码审查流程、发布流程）

❌ **不应提炼为技能的情况：**
1. 内容只是**单一事实/知识点**（如：Docker配置方法）
2. 内容是**日常对话/记录**（如：今天开了个会）
3. 内容是**个人偏好**（如：我喜欢用VSCode）
4. 内容是**一次性经验**，不具备复用价值

**L4→L6提炼判断逻辑：**
```
IF 内容包含多步骤工作流 AND 可复用完成复杂任务：
    提炼为L6技能
ELIF 内容只是单一知识点/事实：
    保持为L4经验
ELIF 内容包含用户明确指令（"记住这个技能"）：
    强制提炼为L6技能
ELSE：
    跳过，不提炼
```

#### 2.4.4 L3-L6整理Prompt规范

系统在调用大模型进行L2→L4、L4→L6整理时，必须明确要求使用中文命名和概括。

**L2→L4分类生成Prompt要求：**
- 明确要求分类名称使用中文概括
- 明确禁止使用 `其他`、`未分类`、`默认` 等无意义名称
- 明确禁止在主题行中出现日期时间
- 明确长度限制（2-8个字）

**L4→L6技能生成Prompt要求：**
- 明确技能定义：技能是复杂工作流的打包，不是简单总结
- 明确复杂技能可以包含简单技能（技能嵌套/组合）
- 明确调用技能是为了完成特定复杂工作
- 明确L6技能内容强制结构（技能名称、目标任务、触发条件、包含步骤/子技能、涉及工具、最佳实践、依赖的子技能、注意事项）
- 明确技能提炼标准（何时应该提炼为技能，何时应保持为L4）
- 明确禁止使用 `其他`、`通用` 等无意义名称
- 明确要求输出结构化的工作流步骤

### 2.5 前端详情页展示规范

#### 2.5.1 详情页布局结构

```
┌─────────────────────────────────────────┐
│  📝 对话记录                              │  ← 标题（从content第一个##提取）
│  ⏰ 2026-04-26 14:30  |  🤖 Hermes Agent │  ← 元数据栏
│  📂 对话记录            |  🏷️ 对话记录     │  ← 分类和标签（中文）
│  ✅ 置信度: 95%                           │
├─────────────────────────────────────────┤
│                                         │
│  ### 用户提问                            │  ← Markdown渲染区（中文排版）
│  如何配置Docker镜像加速器？                 │
│                                         │
│  ### 助手回复                            │
│  在Linux系统中，编辑 /etc/docker/...     │
│                                         │
├─────────────────────────────────────────┤
│  💡 关键信息: Docker镜像加速器配置方法     │  ← 底部信息栏
└─────────────────────────────────────────┘
```

#### 2.5.2 中文映射规则

| API字段 | API值示例 | 前端中文显示 |
|---------|-----------|-------------|
| `source` | `hermes` | `Hermes Agent` |
| `source` | `openclaw` | `OpenClaw Agent` |
| `category` | `conversation` | `对话记录` |
| `category` | `knowledge` | `知识记录` |
| `category` | `task` | `任务记录` |
| `category` | `preference` | `用户偏好` |
| `category` | `insight` | `洞察分析` |
| `confidence` | `0.95` | `95%` |
| `metadata.turn_number` | `5` | `第5轮` |
| `metadata.word_count` | `1200` | `1200字` |

#### 2.5.3 渲染规则

1. **标题**: 提取content中第一个 `## ` 后的文本
2. **元数据栏**: 解析 `**时间**`、`**来源**`、`**会话**` 等字段
3. **正文区**: 完整Markdown渲染，保留中文排版
4. **底部栏**: 提取 `**关键信息**`、`**标签**` 等
5. **标签显示**: 使用中文标签，技术名词可保留英文
