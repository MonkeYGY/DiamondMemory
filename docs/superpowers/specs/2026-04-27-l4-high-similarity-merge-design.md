# L4 高相似归并设计

## 背景

当前系统存在两类与 L4 相关的能力：

- `L2 -> L4` 新生成时，若命中已有相似 L4，会尝试把新内容并入已有总结
- `deduplicate_existing_l4()` 会对历史 L4 做一次全局去重合并

但现有历史去重逻辑过于粗糙：

- 在全库范围内搜索相似 L4，而不是优先限制在同一 `L3/category`
- 相似度阈值较低，容易把“同领域但不同重点”的内容也拉进候选
- 不区分“明显重复”与“仅相关”，导致真正该归并的历史 L4 未被稳定清理

这使得同一 `L3` 下会长期残留多条高度近似的 L4，总结碎片化明显。

## 目标

- 让同一 `L3/category` 下的历史 L4 能自动收敛为更少、更完整的总结
- 只对“高度近似”的 L4 自动归并，边界不清时宁可不合并
- 归并后同步更新数据库、向量索引和知识库 Markdown 文件

## 非目标

- 不进行跨 `L3` 的全库 L4 自动归并
- 不引入新的前端审核流程
- 不调整 L4 详情页结构

## 方案

### 归并范围

- `deduplicate_existing_l4()` 只在同一 `category` 下寻找重复项
- 即使语义相近，只要 `category` 不同，也不自动合并

### 归并判定

- 保留向量召回作为第一层筛选
- 将阈值从当前偏宽松的全局阈值收紧为更高的 L4 归并阈值
- 命中候选后，再要求：
  - 候选也是 `layer == 4`
  - `category` 与当前主记录完全一致
  - 未被本轮处理过

### 主记录选择

- 继续以当前遍历到的记录作为主记录
- 将同组候选依次并入主记录
- 被并入项删除，主记录保留原 `id`

### 内容融合

- 复用现有 `_merge_summary()`，避免再引入第二套 L4 融合逻辑
- 合并后重新生成分类名，但最终仍通过现有 `_normalize_summary_category()` 收口
- 若模型融合失败，沿用当前“文本回退拼接”的兜底行为

### 数据同步

- 主记录更新后：
  - 更新数据库内容与分类
  - 重算主记录 embedding
  - 更新向量元数据中的分类
  - 重新导出对应 Markdown
- 被并入记录删除时：
  - 删除数据库记录
  - 删除向量索引
  - 删除对应 Markdown

### 接入时机

- 历史清理：继续复用 `deduplicate_existing_l4()`
- 深度整理：继续复用现有阶段顺序，不新增独立阶段，只强化 L4 去重阶段的判定逻辑

## 验证

- 同一 `category` 下的两条高度相似 L4 会合并成 1 条
- 不同 `category` 下的相似 L4 不会被自动合并
- 合并后主记录 Markdown 会更新，被并入记录 Markdown 会删除
- 深度整理阶段调用 L4 去重后，`l4_dedup.merged` 会反映实际归并条数
