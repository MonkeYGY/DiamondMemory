# 删除 L3/L5 分类自动迁移到默认分类设计

## 背景

当前“管理分类体系”弹窗删除分类时，前端调用的是 `DELETE /api/config/categories/{category_id}`。这条链路目前只删除 `categories` 表中的分类记录，不会同步迁移该分类下的内容型记忆。

项目中已经存在另一套相关逻辑：

- 删除 `L3` 记忆本体时，会将相关 `L4` 迁移到 `未归档`
- 删除 `L5` 记忆本体时，会将相关 `L6` 迁移到 `未分类`

但用户从“分类管理”入口删除时，并不会触发这套逻辑，因此会出现行为不一致。用户希望统一为：

- 手动删除 `L3` 分类后，原属于该分类的 `L4` 自动进入 `L3` 默认分类 `未归档`
- 手动删除 `L5` 分类后，原属于该分类的 `L6` 自动进入 `L5` 默认分类 `未分类`
- 如果默认分类不存在，系统自动创建

## 目标

- 删除 `L3` 分类时，将对应 `L4` 自动迁移到 `未归档`
- 删除 `L5` 分类时，将对应 `L6` 自动迁移到 `未分类`
- 默认分类记录不存在时自动补建
- 删除默认分类本身时进行保护，避免兜底分类被误删
- 保持数据库、向量元数据和知识库导出文件路径一致

## 非目标

- 不修改 L1/L2 的状态与分类逻辑
- 不引入新的默认分类名称
- 不改变现有“删除记忆本体”的接口路径
- 不在本次实现中重构整个分类体系管理架构

## 方案

### 删除链路收口

将分类删除的业务逻辑从单纯的 `store.delete_category(category_id)` 升级为经由服务层处理：

- `config_routes.py` 不再直接删除分类记录
- 改为调用 `memory_service` 中新的分类删除编排方法

这样可以把以下动作收口在一个地方：

- 查询被删除分类信息
- 判断是否为默认分类
- 确保默认分类存在
- 批量迁移关联内容
- 更新导出文件
- 最后删除分类记录

### 默认分类规则

- `L3` 默认分类固定为 `未归档`
- `L5` 默认分类固定为 `未分类`

如果对应默认分类记录不存在：

- 自动在 `categories` 表中创建默认分类
- 层级分别保持为 `3` 或 `5`
- 不设置父分类

### 迁移规则

删除 `L3` 分类时：

- 查出该分类名
- 将所有 `category == 被删分类名` 的 `L4` 记忆更新为 `未归档`
- 同步更新对应向量元数据中的 `category`
- 重导出对应 Markdown 文件，使其移动到 `总结经验/未归档/`

删除 `L5` 分类时：

- 查出该分类名
- 将所有 `category == 被删分类名` 的 `L6` 记忆更新为 `未分类`
- 同步更新对应向量元数据中的 `category`
- 重导出对应 Markdown 文件，使其移动到 `技能/未分类/`

### 默认分类删除保护

禁止删除以下分类：

- `L3` 的 `未归档`
- `L5` 的 `未分类`

后端应返回明确错误信息，前端弹出错误提示，不做删除。

## 前端交互

“管理分类体系”弹窗中的删除确认文案从旧的：

- “该操作不会删除记忆，但会使这些记忆变为无分类”

改为新语义：

- 删除 `L3` 分类时：提示相关 `L4` 会自动迁移到 `未归档`
- 删除 `L5` 分类时：提示相关 `L6` 会自动迁移到 `未分类`

如果用户尝试删除默认分类，前端显示后端返回的保护性错误提示即可，不需要额外前端硬编码拦截。

## 影响范围

- `backend/app/api/config_routes.py`
  - 分类删除接口改为走服务层编排
- `backend/app/services/memory_service.py`
  - 新增删除分类编排方法
  - 新增确保默认分类存在的方法
  - 复用或扩展现有子记忆迁移逻辑
- `backend/app/storage/sqlite_store.py`
  - 复用已有分类查询、创建、删除方法
- `frontend/src/renderer/views/MemoryView.vue`
  - 更新删除分类确认文案

## 边界处理

- 被删分类下没有任何 `L4/L6` 内容时，仍允许正常删除分类
- 默认分类已存在时不重复创建
- 默认分类自动创建失败时，整个删除动作终止，避免子内容迁移到无效分类
- 只迁移直属内容层：
  - `L3 -> L4`
  - `L5 -> L6`

## 验证

- 删除普通 `L3` 分类后，相关 `L4` 自动改到 `未归档`
- 删除普通 `L5` 分类后，相关 `L6` 自动改到 `未分类`
- 默认分类原本不存在时，首次删除后会自动创建并成功迁移
- 删除默认分类 `未归档` / `未分类` 时被拒绝
- 迁移后知识库目录中的文件也进入对应默认分类目录
- 前端删除提示文案与实际行为一致

## 结论

本方案通过把“分类删除”统一收口到服务层编排，补上默认分类自动创建、删除保护和迁移重导出逻辑，确保用户无论从哪个分类管理入口删除 `L3/L5`，其下属 `L4/L6` 都会稳定进入默认分类，而不会出现“无分类”或行为不一致的问题。
