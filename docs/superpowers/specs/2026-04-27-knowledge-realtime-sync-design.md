# 知识库实时关联同步设计

## 背景

当前知识库左侧文件树已经具备刷新能力，但记忆页里会影响 `L3-L6` 的操作完成后，前端多数只是触发了“文件树刷新”，没有统一先触发一次后端知识库映射重建。因此只要某条链路没有立即把文件系统写到最新状态，知识库中“总结经验/技能”就会出现与 `L3-L6` 内容不同步的现象。

## 目标

- 会影响 `L3-L6` 的操作成功后，知识库与记忆内容立即保持一致
- 同步顺序固定为：业务成功 -> 后端重建知识库映射 -> 前端刷新文件树
- 对重复触发增加并发保护，避免短时间内多次重建

## 方案

### 统一同步方法

- 在前端封装统一的 `syncKnowledgeTree` 方法
- 该方法内部执行两件事：
  - 调用后端 `/api/knowledge/rebuild-memory-exports`
  - 成功后触发知识库文件树刷新事件
- 增加模块级并发锁；若已有同步在执行，后续调用直接复用同一个 Promise

### 接入触发点

以下场景成功后统一调用 `syncKnowledgeTree`：

- 新建记忆
- 删除记忆
- 分类修改
- 分类删除
- 快速整理完成
- 深度整理完成

### 知识库页入口

- `App.vue` 中进入知识库页时，继续调用同一个 `syncKnowledgeTree`
- 这样首次进入知识库时可补齐历史状态，后续记忆页操作则可保持实时一致

## 非目标

- 不改知识库页面布局
- 不新增新的轮询机制
- 不改动知识库文件树的展示规则

## 验证

- 新建 `L3/L4/L5/L6` 后，知识库立刻显示最新目录与文件
- 删除 `L3/L4/L5/L6` 后，知识库立刻移除或迁移对应项
- 快速整理、深度整理完成后，知识库立刻和记忆层级一致
- 连续快速触发多个操作时，不会并发发起多次重复重建请求
