# L4/L6 父级标签显示设计

## 背景

记忆管理页当前会展示记忆自身的普通标签与分类信息，但对于 `L4` 和 `L6` 这两类内容型记忆，界面没有明确展示其上级归属。用户希望在每条 `L4/L6` 记忆上直接看到所属的上级标签，避免仅靠 `category` 猜测其目录归属。

本次需求明确为：

- `L4` 显示所属 `L3` 标签
- `L6` 显示所属 `L5` 标签

## 目标

- 由后端为记忆数据统一补充父级标签字段
- 前端在记忆列表与详情页统一展示该字段
- `L4` 显示 `L3: xxx`
- `L6` 显示 `L5: xxx`
- 不改动现有普通 `tags` 与 `category` 的业务含义

## 非目标

- 不调整数据库表结构
- 不修改 `tags` 的存储方式
- 不改动知识库导出目录结构
- 不强制迁移历史数据，只在接口返回时尽量解析现有父级关系

## 方案

### 后端字段

在记忆列表接口返回的每条记忆对象中新增标准字段 `parent_label`。

建议结构：

```json
{
  "layer": 3,
  "name": "记忆写入机制"
}
```

规则如下：

- `L4` 返回所属 `L3` 的 `parent_label`
- `L6` 返回所属 `L5` 的 `parent_label`
- 其他层级返回 `null` 或不返回该字段

### 父级解析规则

优先使用当前系统内已经稳定存在的归属关系进行推导：

- `L4` 按所属分类名匹配对应的 `L3`
- `L6` 按所属分类名匹配对应的 `L5`
- 若存在多个同名候选，优先选择当前层级匹配且可稳定命中的记录

这样可以兼容现有数据库，无需先做历史迁移。

### 前端展示

#### 列表卡片

- 在 `MemoryView.vue` 的标签区域增加父级标签展示
- 仅 `L4/L6` 展示
- 展示文案固定为：
  - `L4` -> `L3: <name>`
  - `L6` -> `L5: <name>`
- 视觉样式与普通标签区分，避免与用户自定义标签混淆

#### 详情弹窗

- 在详情元信息区域增加父级标签信息
- 与列表展示保持一致
- 无父级时不展示该项

## 边界处理

- 某条 `L4/L6` 没有 `category` 时，不显示父级标签
- 当前数据无法解析出对应 `L3/L5` 时，不显示父级标签
- 不因父级缺失而阻断整个记忆列表的渲染
- 不把 `parent_label` 混入原始 `tags` 数组，避免污染筛选逻辑

## 影响范围

- `backend/app/services/memory_service.py`
  - 为记忆列表结果补充 `parent_label`
- `backend/app/api/memory_routes.py`
  - 继续复用现有列表接口，无需新增接口
- `frontend/src/renderer/views/MemoryView.vue`
  - 在列表卡片和详情弹窗展示父级标签

## 验证

- 过滤到 `L4` 时，列表中每条记录显示对应 `L3` 标签
- 过滤到 `L6` 时，列表中每条记录显示对应 `L5` 标签
- 打开 `L4` 详情时显示 `L3: xxx`
- 打开 `L6` 详情时显示 `L5: xxx`
- 旧数据若无法解析父级，界面正常显示且不报错

## 结论

本方案采用“后端补充标准字段，前端统一展示”的方式实现 `L4/L6` 父级标签展示，既能兼容现有数据结构，也能避免把目录归属逻辑散落在多个前端位置，后续如需在更多页面复用该字段也可直接扩展。
